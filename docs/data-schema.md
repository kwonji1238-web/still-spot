# 데이터 구조 설명 (data-schema)

`data/`의 JSON 파일과 서비스가 데이터를 다루는 규칙을 정리한 문서입니다. 필드 설명은 공식 명세가 아니라 **필드 이름과 실제 값을 보고 정리한 것**이라 추정이 섞인 곳은 "(추정)"이라고 적었습니다. 인증키는 이 문서에 적지 않았습니다.

- "비어 있음" = 값이 없음(null)이거나 빈 글자·공백뿐인 경우입니다.
- `data/`의 `cinemap.json`, `attractions.json`, `restaurants.json`, `posters.json`은 원본 그대로 두고 수정하지 않습니다. 화면에 맞는 변환은 어댑터(`src/data.js`)가 하고, 배포본(`dist/data/`)에는 `scripts/slim.mjs`가 화면에서 쓰는 필드만 남긴 사본을 만듭니다.

## 0. 파일 한눈에

| 파일 | 건수 | 만든 방법 |
|---|---|---|
| `cinemap.json` | 2,193건 | 씨네맵 API 원본(작품명·장소명·주소) + 카카오로 변환한 좌표·상태 (`scripts/cinemap.py`) |
| `attractions.json` | 213건 | 부산명소 API 원본 그대로 |
| `restaurants.json` | 470건 | 맛집 API에서 일부 항목만 저장 + 분류 항목 4개 추가 (`scripts/restaurants.py`, 원본 471건 중 좌표 문제 1건 제외) |
| `posters.json` | 409개 작품 | TMDB 검색 결과 (`scripts/posters.mjs`) |
| `scenes.json` | 14건 | 촬영지 장면 설명을 직접 조사해 작성(출처는 `scenes-sources.md`) |

규모(작품 수·장소 수):

| 기준 | 작품 | 촬영 기록 | 장소(같은 이름·주소는 1곳) |
|---|---|---|---|
| 원본 `cinemap.json` | 428개 | 2,193건 | 1,069곳 |
| 화면(이름 앞에 `[폐업]`·`[페업]`이 붙은 67건 제외) | 425개 | 2,126건 | — |

좌표가 없는 촬영 기록은 원본 111건(5.1%), 화면 기준 110건입니다. 같은 장소로 세면 58곳입니다.

## 1. cinemap.json (촬영지)

| 필드 | 내용 | 비어 있는 건수 | 비어 있는 비율 | 값 형태 |
|---|---|---|---|---|
| `opusNm` | 작품명 | 0 | 0.0% | str |
| `plcNm` | 촬영 장소 이름 | 0 | 0.0% | str |
| `roadNmAddr` | 촬영지 도로명주소(원본, 모양이 제각각) | 0 | 0.0% | str |
| `lat` | 위도 (카카오로 변환한 값, 변환 실패 시 비어 있음) | 111 | 5.1% | float |
| `lng` | 경도 (카카오로 변환한 값) | 111 | 5.1% | float |
| `변환상태` | 좌표 변환 결과: 성공 / 키워드검색성공(위치가 틀릴 수 있음) / 실패 | 0 | 0.0% | str |

- 화면에서 쓰는 필드: `opusNm`, `plcNm`, `roadNmAddr`, `lat`, `lng`, `변환상태`(지금은 저장만 하고 화면에는 쓰지 않음).
- 작품이 영화인지 드라마인지 구분하는 필드는 **없습니다**. 개봉연도·감독·출연·장면 설명·이미지도 없고, 있는 것은 작품명, 장소명, 도로명주소, (변환한) 좌표뿐입니다.
- `변환상태`는 성공 2,054 / 키워드검색성공 28(위치가 틀릴 수 있음) / 실패 111입니다.

### 서비스가 다루는 규칙
- 촬영지 id는 원본 순서 번호(`s0`, `s1`, …)이고, 거르기 전에 정해서 바뀌지 않습니다.
- 이름 앞에 `[폐업]`(오타 `[페업]` 포함)이 붙은 촬영지는 화면에 내지 않습니다. `[철거]`는 그대로 보입니다.
- 같은 장소(이름·주소가 같음)를 찍은 작품은 "이 장소에서 촬영된 작품"으로 묶어 보여 줍니다.
- 좌표가 없는 촬영지는 핀이 없고, 목록에서 번호 없이 "주소만 표시"로 맨 뒤에 둡니다. 근처·코스·지도 버튼은 숨깁니다.
- 직선 거리는 두 좌표 사이의 직선 거리입니다.

## 4. posters.json (작품 포스터·정보)

- `{작품명: {path, year, genres, ...}}` 모양입니다. 촬영지 데이터에는 포스터가 없어서 TMDB 검색으로 작품명(앞의 서비스명은 뗌)에서 찾습니다. 찾은 제목이 작품명과 전혀 다르면 엉뚱한 작품이라 항목째 버립니다.
- 화면은 `https://image.tmdb.org/t/p/w185` + `path`로 포스터를 보이고, 개봉·첫 방영 연도(`year`)와 장르(`genres`, 화면에는 최대 3개)를 포스터 옆에 씁니다. 값이 없으면 그 줄이 빠지고, 포스터가 없으면 서비스 로고 칸으로 보입니다.
- 같은 파일에 출연(`cast`)·줄거리(`overview`)도 있지만 지금 화면에서는 쓰지 않아 배포본에는 넣지 않습니다.
- 409개 작품에 포스터가 있습니다(원본 428개 중).

## 5. scenes.json · 촬영지 사진

- `scenes.json`: `"작품명|장소명": "장면 설명"`. 있는 촬영지에만 장면 설명이 보입니다.
- 촬영지 사진은 `src/settings.js`의 `SPOT_PHOTOS`(장소명 → 사진 파일 배열)와 `images/`에서 정합니다. 이미지 주소를 임의로 만들지 않습니다.

## 6. 근처 후보 반경 참고

좌표 있는 촬영지 2,082곳(원본 기준) 중 후보(관광지 최대 2 + 식당 최대 1 + 카페 최대 1)가 채워지는 비율을 반경별로 센 값입니다(코스에 식당을 넣던 때 계산한 참고용입니다). 코드의 코스 반경은 5km에서 시작해 관광지·카페가 모이지 않으면 8km, 12km로 넓히고(`COURSE_RADIUS_STEPS_M`), 근처 미리보기와 근처 장소 핀은 3km입니다(`NEARBY_RADIUS_M`).

| 반경 | 관광지 2곳 | 식당 1곳 | 카페 1곳 | 후보 0곳 | 4곳 모두 |
|---|---|---|---|---|---|
| 1km | 57.4% | 84.7% | 33.8% | 10.1% | 26.2% |
| 2km | 86.8% | 93.1% | 61.9% | 2.5% | 60.5% |
| 3km | 95.4% | 96.9% | 81.9% | 1.6% | 80.5% |

## 7. 배포용 데이터

`scripts/build.mjs`는 위 파일에서 화면과 AI 코스 설명이 쓰는 필드만 남겨 `dist/data/`에 둡니다(필드 목록은 `scripts/slim.mjs`). 원본에는 영향이 없고, 나중에 다른 필드가 필요하면 목록에 이름을 더하고 다시 빌드하면 됩니다. 줄인 사본으로 만든 결과가 원본으로 만든 결과와 같은지 `tests/core.test.js`가 확인합니다.
